# 운영자 5곳 파일럿 실행 키트

이 문서는 **모집·동의·측정·분석을 실행하기 위한 준비물**이다. 현재 실제 운영자 모집·인터뷰·실운영 데이터·매출 근거는 없다. 테스트 fixture는 실행을 확인하기 위한 코드이고 운영자 다섯 곳을 확보했다는 증거가 아니다. 원래 이슈 #23은 실제 운영자와 동의받은 결과가 있어야 완료할 수 있으므로 이 준비만으로 닫지 않는다.

## 모집 설계

서로 다른 보호 작업의 운영자 최소 5곳을 모집한다. 예시 할당은 연락 폼/커뮤니티 가입/전자상거래/리워드/계정 복구 각 1곳이다. 각 운영자는 보호된 작업, 기존 방어, 실제 abuse 판정 기준, 접근성 요구와 지원 경로를 사전 정의한다. 서비스 이름·담당자 이메일·계약·동의 서명은 소유자 통제의 비공개 문서에 보관하고 공개 aggregate에는 넣지 않는다.

연락 문안은 다음과 같으며 **현재 전송하지 않았다**. 실제 발송 대상·채널은 별도 사용자 지시와 적합한 연락 근거가 필요하다.

> 제목: Kechap 사람 검증 수단 연동·운영 비용 파일럿 참여 안내
>
> Kechap은 기존 인증 공급자를 선택·서버 검증·교체하는 초기 오픈소스입니다. 귀 서비스의 보호된 작업에서 기존 방어와 변경 후 흐름의 완료율·확인된 abuse·지원 문의·비용·설치/유지 시간을 비교하고자 합니다. 자동화가 완전히 차단되거나 실제 인간·신원·유일성이 증명된다고 약속하지 않습니다.
>
> 참여는 자발적이며 운영자가 통제하는 테스트 또는 제한된 트래픽부터 시작합니다. 원본 사용자 이벤트·이름·이메일·IP·영상·음성은 연구 aggregate로 수집하지 않습니다. 설정·복구·중단 책임과 데이터 처리 범위를 먼저 합의합니다. 중도 철회·실패·비용 증가도 결과에 포함하며 후원이나 긍정적 후기를 조건으로 하지 않습니다.
>
> 참여 가능 여부와 보호 작업·배포 여건을 논의할 수 있는지 알려주세요. 실제 트래픽 변경이나 데이터 접근은 동의·범위 합의 전 수행하지 않습니다.

## 동의와 운영 범위 양식

운영자마다 다음을 비공개로 서명·확인한다. 실제 법률 동의 양식이나 개인정보 처리 계약을 이 템플릿만으로 대체하지 않는다.

- 연구 revision과 역할: 운영 책임자, 배포 승인자, 보안 신고·지원 담당, 중단 요청 경로.
- 대상 action과 제외 트래픽: 운영자의 실제 정상·abuse 정의, 내부 시험·테스트 키·모니터 제외, 반복 요청의 분모 처리.
- 적용 방식: 테스트환경 → 소수 canary → 확대 조건, 기존 방어와 동등/추가 보장, 동등 접근성 복구 경로.
- baseline·intervention 기간, 휴일·캠페인·유입 변화·공급자 장애·제품 변경 기록과 비교 방법.
- 수집 범위: 서비스가 자체 집계한 수치만 연구 입력. 개별 사용자 PII·생체 원본·토큰을 전달하지 않음.
- 원본 업무 데이터의 관리 주체·보존·삭제; 연구 aggregate는 예를 들어 파일럿 종료 후 90일에 재검토/삭제. 실제 기간은 합의해 고정.
- 동의 버전·시각·철회 방식. 철회 시 새 수집 중단·비공개 raw/연락정보 삭제·공개 report 철회 또는 익명화 가능 범위를 설명.
- 비용·보상·지원 부담, 실패·해지 결과 공개 여부, 민감한 공격 상세는 비공개 보안 경로로 처리.
- 사업 이름·로고·고객 사례 공개 동의는 연구 참여 동의와 별도 선택이다.

익명 operator ID는 `op_` 뒤에 무작위 8바이트의 lowercase hex를 붙인다. 실제 도메인·회사명·이메일을 해시해 ID로 쓰지 않는다. 역추적 가능 매핑은 운영자가 보유하고 연구 파일과 분리한다. 철회 시 매핑을 이용해 해당 aggregate를 제거하고 이전 공개 결과에도 withdrawn/superseded 사유를 기록한다. 분석기는 동의 철회 항목을 real aggregate에 포함하지 않는다.

## 비교 창과 지표 정의

기본은 비슷한 요일·기간·유입을 갖는 baseline 7~14일과 intervention 7~14일을 사전 등록한다. 안전하게 가능한 경우 동시 무작위 배정을 사용하되 그 배정·분모·클러스터와 통계 분석은 별도로 등록한다. 순차 관찰 연구에서 개선된 수치를 곧바로 원인·보안 효과로 해석하지 않는다.

| 필드 | 실제 의미 |
| --- | --- |
| eligibleRequests | 사전에 정한 보호 작업을 시작한 요청 수. 테스트·모니터 제외 기준과 반복 요청 처리 고정 |
| completedActions | 검증뿐 아니라 실제 보호된 업무까지 완료된 수. 자동 retry가 중복 완료로 세어지지 않도록 집계 |
| confirmedAbusiveActions | 동일한 운영자 abuse 판정 기준으로 확인된 완료 업무 수. CAPTCHA 미통과 수가 아님 |
| supportTickets | 해당 흐름의 지원 문의. 일반 문의와 분리하고 개인정보 원문은 전달하지 않음 |
| providerCostUsd | 실제 공급자 요금. 무료 크레딧·할인 적용 상태는 비공개 운영 노트로 별도 기록 |
| infrastructureCostUsd | 해당 측정 창의 서버·네트워크·저장소 배분 비용. 산정법 고정 |
| installationHours | 설치·자격증명·테스트·문서·장애 대응 준비에 든 실제 시간 |
| maintenanceHours | 측정 창의 업데이트·장애·지원·설정 유지에 든 실제 시간 |
| failures | outage/false-reject/integration/accessibility/cost/other별 건수. 사용자 원문·PII 없음 |
| cancellationReason | privacy/accessibility/cost/no-value/integration-failure/operator-capacity/other 코드. 해지 사례도 삭제하지 않음 |
| willingnessToPay | 인터뷰에서 말한 월 금액 또는 미응답 null. 구매·매출·유료 전환으로 계산하지 않음 |

완료율 분모는 eligibleRequests다. abuse는 eligible와 completed 두 분모를 모두 보고한다. 문의·비용 역시 1,000 eligible 기준으로 비교한다. 설치 시간은 일회성이고 maintenance는 관찰 기간에 속하므로 합쳐 운영비로 단순 환산하지 않는다. 실제 원가를 원하면 운영자가 시간당 단가와 비용 배분법을 별도 공개해야 한다.

관찰 기간 길이 차이가 10%를 넘거나 보호 작업·abuse 정의·유입 inclusion·외부 변경 통제가 일치하지 않으면 분석기는 deltas를 `null`로 반환한다. 기간을 맞췄다고 휴일·계절·캠페인 효과가 제거되지는 않는다. 어떤 불확실성도 숨겨 결과를 비교 가능하다고 주장하지 않는다.

## 입력 계약과 분석 실행

정식 [pilot.schema.json](../benchmarks/pilot.schema.json)은 한 revision의 `operators` 배열을 받는다. 각 operator는 source(`real-operator`, `fixture`, `synthetic`), 익명 ID, productType, 동의·withdrawn 시각, provenance hash와 독립 검토 여부, baseline/intervention 수치, 비교 flags, 실패·해지·지불 의향으로 구성된다. 허용하지 않은 이메일·회사명·사용자 이벤트 같은 field는 schema에서 거절한다. 공개 hash는 입력 보고서의 무결성 표식이지 진위·동의 확인을 자동으로 증명하지 않는다.

```bash
node scripts/analyze-pilots.js /private/path/pilot-aggregates.json .local/pilots/report.json
```

- `source:fixture` 또는 `synthetic`는 real operator count·개별 real report·aggregate에 포함하지 않는다.
- real이라고 표기해도 동의가 없거나 철회됐거나 baseline 시작 전 동의가 아니거나 검토된 provenance가 없으면 제외한다.
- active 또는 인터뷰가 아직 없는 파일럿, null/0 분모·빠진 비용은 진행 중/불완전 결과이며 비교 완료로 세지 않는다.
- 최소 **서로 다른 제품 유형 5곳의 real·동의·독립 검토·비교 가능한 결과**가 있어야 aggregate를 생성한다. 아직 없으면 status는 `insufficient-real-comparable-pilots`, aggregate와 revenue는 `null`이다.
- 다른 사례의 분모를 섞어 개인별 평균을 전체 성공률로 제시하지 않는다. aggregate는 합산 분모의 descriptive 값이고 causal/security claim이 아니다.
- 날짜·단조 창, 중복 operator ID, 완료 수>시작 수, abuse 수>완료 수, 음수 비용/시간과 중도 철회 상태를 검사한다.

## 공개 결과와 의사결정

외부 검토자는 원 운영자 동의와 측정 정의·기간·요약 hash·분모·비용 계산을 비공개 또는 허가된 artifact로 확인한다. 공개 카드는 익명 ID·제품 유형·기간·배정 방법·비교 경고·분모·완료/abuse/지원/비용·설치/유지 시간·실패/해지 코드·stated willingness-to-pay를 포함한다. 표본이 작거나 재식별 가능하면 제품 유형·기간의 공개도 더 거칠게 묶고 해당 카드의 수치를 공개하지 않는다.

파일럿 다섯 곳이라는 숫자는 시장 검증이나 통계적 유의성을 보장하지 않는다. 효과 크기·불확실성·동시 변경·부정 결과·설치/유지 비용과 접근성 손실을 검토한 뒤 계속/수정/중단을 결정한다. 실제 사람 완료율이나 VLM 차단율은 이 운영자 aggregate만으로 만들어낼 수 없다. 실험 protocol의 참가자·공격 예산·모델·시간·통계 검증은 별도로 수행한다.

## 실행 기록과 남은 차단 조건

분석기 테스트 fixture 7개는 schema 거절, source 분리, 5개 이상 branch의 산술, 철회·비교 불가·실패·null을 확인한다. 테스트에서 `source`를 real로 바꾼 branch 역시 메모리상의 **fixture**이며 실제 운영자 결과로 저장하거나 공개하지 않는다. 실제 CLI에는 빈 입력을 실행했고 `insufficient-real-comparable-pilots`, real count 0, aggregate null을 확인했다.

실제 완료에는 운영자 5곳의 별도 모집·동의·배포 승인·관찰 기간·인터뷰·독립 검토가 필요하다. 연락 문안을 대신 전송하거나 운영자/동의/측정치를 만들어 넣지 않았다. #23은 이 실제 수용 조건이 충족될 때까지 열린 상태로 유지해야 한다.
